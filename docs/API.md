# WireScope API

[English](en/API.md)

## Версионирование

Канонический HTTP API WireScope публикуется под префиксом `/api/v1`.

Например:

```text
GET  /api/v1/health
GET  /api/v1/environment
POST /api/v1/audits
GET  /api/v1/jobs/{job_id}
```

Старый префикс `/api` пока сохранён как compatibility alias. Это нужно, чтобы текущий GUI и внешние клиенты можно было перевести на v1 без единовременного обновления всех компонентов.

```text
/api/v1/...   канонический API
/api/...      временный compatibility alias
```

Compatibility-маршруты намеренно не публикуются в OpenAPI. Swagger/ReDoc показывают только `/api/v1/*`.

## Совместимость

На переходном этапе оба префикса вызывают одни и те же handlers и используют одинаковые модели, авторизацию и проверки scope. Отдельной реализации «старого API» нет.

Некоторые ссылки, возвращаемые в response-моделях (`result_url`, `pcap_url`, ссылки на export отчёта), пока используют старый `/api/*`. Они остаются рабочими благодаря compatibility alias. После перевода frontend на `/api/v1` эти ссылки можно переключить отдельным совместимым изменением.

## Авторизация

Авторизация одинакова для обоих префиксов:

- `GET /health`, `/status`, `/ready` — публичные;
- `POST /auth/login` и `/auth/logout` — публичные;
- остальные operational routes требуют сессию;
- mutating routes требуют роль `auditor`, кроме смены собственного пароля.

Сессия хранится в HttpOnly cookie. Подробнее: [SECURITY_MODEL.md](SECURITY_MODEL.md).

## Политика изменений

Для v1 действует простое правило: совместимые добавления можно делать внутри `/api/v1`, а несовместимое изменение контракта должно получать новую major-версию API, а не молча ломать существующий маршрут.
